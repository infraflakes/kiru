---
title: std
description: The high-frequency builtins at the std root.
---

`std::` holds the builtins used most often: output, the shell command builder,
and `quote`. The category modules hold the rest: `std::process`, `std::io`,
`std::fs`, `std::text`, `std::vec`, `std::env`, `std::path`, `std::time`, and
`std::cli`.

The built-in types are declared in categories: `std::text` declares `txt`,
`std::vec` declares `Vec<T>`, and `std` declares `bool` and `int`. A program
writes them bare only after the matching `use`; a qualified `std::text::txt`
works without one. `std::map` and `std::set` are not built-ins: they declare the
`Map<K, V>` and `Set<K>` records ([std::map](/stdlib/map/),
[std::set](/stdlib/set/)).

<details>
<summary><code>print</code> — write a line to stdout</summary>

```kiru
std::print(message: txt)
```

Writes `message` to stdout with a trailing newline.

```kiru
std::print("hello");
```

</details>

<details>
<summary><code>fail</code> — write an ERROR line and stop the run</summary>

```kiru
std::eprint(message: txt)
```

Writes an `ERROR:` line to stderr, red when stderr is a terminal, then stops the
run. Because `fail` always stops the run, calling it never returns.

```kiru
std::eprint("missing token");
```

Related: [Panic and Failure](/failure/panic/).

</details>

<details>
<summary><code>info</code> — write an INFO line</summary>

```kiru
std::info(message: txt)
```

Writes an `INFO:` line to stdout; the prefix is yellow when stdout is a
terminal.

```kiru
std::info("starting");
```

</details>

<details>
<summary><code>command</code> — build a command</summary>

```kiru
std::command(line: txt) -> std::Command
```

Starts a command under construction. Each setting method returns a new
`Command`, so calls chain. `.run()` runs the line and returns the exit code
as an `int`; `.capture()` runs it and returns a `std::Output` of `code`, `out`,
and `err`. `std::Output`'s fields are `pub`, so a program reads them directly;
`std::Command` is a `pub` type a program can name and hold, but its fields are
private, reached only through its methods.

| | |
| --- | --- |
| `command.dir(path: txt) -> Command` | the working directory |
| `command.env(name: txt, value: txt) -> Command` | export one variable |
| `command.timeout(seconds: int) -> Command` | bound the run |
| `command.stream(stream: txt, target: txt) -> Command` | attach `stdin`, `stdout`, or `stderr` to a path |
| `command.run() -> int` | run and return the exit code |
| `command.capture() -> std::Output` | run and return `code`, `out`, and `err` |

```kiru
use std;
let code: int = std::command("bun run build").dir("docs").run();
```

Related: [Running Commands](/commands/running-a-command/).

</details>

<details>
<summary><code>quote</code> — escape text as one shell word</summary>

```kiru
std::quote(text: txt) -> txt
```

Wraps `text` in single quotes and escapes every embedded quote as `'\''`, so
the shell reads exactly the text and nothing else.

```kiru
use std;
use std::text;
let argument: txt = "a b";
let line: txt = "echo @(std::quote(argument))";
```

</details>

`std::split` and `std::join` are the text and vec helpers; they are documented
on [std::text](/stdlib/text/) and [std::vec](/stdlib/vec/).
